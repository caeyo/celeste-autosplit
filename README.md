# celeste-autosplit

An auto splitter for Celeste that runs on every LiveSplit host.

## Repository layout

| Folder | What | Built with |
|---|---|---|
| [`autosplitter/`](autosplitter/) | The auto splitter itself, compiled to `celeste_autosplit.wasm`. The only splitting engine on every host. | Rust (`cargo`) |
| [`component/`](component/) | `celeste-autosplit.dll`, the LiveSplit (Windows) component that wraps the wasm module and provides the settings editor and legacy migration. | .NET SDK (`dotnet`) |
| [`schema/`](schema/) | `settings-schema.json`, the shared settings schema consumed by the component and the website. | — |
| [`site/`](site/) | The GitHub Pages settings editor for `.lss` files, for livesplit-core hosts. | Static HTML/CSS/JS |
| [`layouts/`](layouts/) | The memory layouts the auto splitter reads, as Rust: each vanilla flavour's, generated by the layout probe, and Everest's, transcribed from its source. | — |
| [`tools/layout-probe/`](tools/layout-probe/) | Measures the game's memory layout inside each flavour's own runtime. | .NET SDK (`dotnet`) |
| [`harness/`](harness/) | The live check: runs the wasm module on livesplit-core's timer, against the real game that the layout probe holds. | Rust (`cargo`) |
| [`traces/`](traces/) | What the auto splitter reads from the real game, update by update, while CelesteTAS plays a TAS, for each TAS file there. | — |
| [`tools/trace-recorder/`](tools/trace-recorder/) | Records the traces: an Everest mod, and a script that records with it in an install of the game of its own. | .NET SDK (`dotnet`) |
| [`update.xml`](update.xml) | LiveSplit's update manifest for the component. | — |

## Building

```sh
cd autosplitter && cargo b --release    # wasm module
cd component && dotnet build            # LiveSplit component (+ dotnet test, after the wasm)
cd harness && cargo build --release     # live check, against the layout probe (see its README)
cd tools/trace-recorder && dotnet build # trace recorder (see its README to record)
node site/serve.mjs                     # website at http://localhost:8000
```

See each folder's README for details.

## CI and releases

| Workflow | Runs |
|---|---|
| `autosplitter.yml` | Builds the wasm module, and runs clippy and fmt on both Rust crates (the auto splitter and the harness), failing on any warning. On changes to `autosplitter/`, `layouts/` or `harness/`. |
| `component.yml` | Build and test on Windows on changes to `component/`, `schema/`, `autosplitter/` or `layouts/` (the tests run the wasm module). |
| `site.yml` | Deploys `site/` (plus the schema) to GitHub Pages on pushes to `master`. |
| `layouts.yml` | Runs the layout probe against each vanilla flavour's real game files, which come from a private repository, then the live check of the wasm module, built with the layout the probe wrote, against the game the probe holds. On dispatch, it then opens a pull request with the regenerated layouts. It also runs for pull requests from this repository that change `autosplitter/`, `layouts/`, `harness/` or the probe, and fails them if a committed layout isn't the one the probe writes. |
| `release.yml` | On a `v*` tag: builds both, then publishes `celeste-autosplit.dll` and `celeste_autosplit.wasm` together. |

Releasing:

1. Set `<Version>` in `component/CelesteAutosplit/CelesteAutosplit.csproj`.
2. Push a matching tag, for example `v1.0.0`.
3. After the release is published, add the version to `update.xml` and commit it.
